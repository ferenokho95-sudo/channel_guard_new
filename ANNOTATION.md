# Инструкция разметчику

Единица: отдельное сообщение. Метка означает намерение продолжить взаимодействие за пределами исходной платформы; наличие контакта само по себе недостаточно. При отсутствии контекста оставьте pending, не угадывайте.

| Сообщение | label | Причина |
|---|---:|---|
| Напиши в тг, ник @example | 1 | Предложение продолжить общение |
| Пришли номер, свяжусь напрямую | 1 | Запрос внешнего канала |
| Пиши на user [собака] example [точка] invalid | 1 | Обфусцированный контакт |
| Не пиши в Telegram, общаемся здесь | 0 | Отказ от перехода |
| Заказ 89261234567 доставлен | 0 | Номер заказа |
| Как настроить Telegram? | 0 | Упоминание без перехода |
| В документации указан example.invalid | 0 | Справочная ссылка |

Исправляйте label и только после проверки ставьте approved. rejected — испорченные, нерелевантные или неразрешимые примеры. Для надежной оценки используйте минимум двух независимых разметчиков, разрешайте расхождения отдельно. Входной корпус здесь синтетический, ручная проверка не заявляется.

Все реплики одного диалога, одного исходного сообщения и его аугментации должны иметь общий group_id. Для шаблонных данных group_id соответствует шаблону. Удаляйте точные и близкие дубликаты, включая разные группы. Примеры содержат учебные несуществующие контакты. Реальные сообщения используйте только при наличии права на обработку; обезличьте контакты до передачи внешней LLM, сохраняя структуру обфускации.

## LLM как помощник

Экспортируйте инструкции и пачки по 20 сообщений:

```bash
python -m guard.llm_tasks export --data data/demo.csv --out data/llm_tasks.jsonl
```

Передайте содержимое отдельной строки LLM. Она должна вернуть по одной JSON-строке на каждое сообщение: id, label, uncertain, reason. Соберите ответы без Markdown в predictions.jsonl. Импорт не считает их проверенными человеком:

```bash
python -m guard.llm_tasks import --data data/demo.csv --predictions data/predictions.jsonl --out data/llm_draft.csv
```

Обоснования и флаг uncertain сохраняются в соседнем audit.json. Просмотрите их, затем проверьте CSV во вкладке «Разметка». Для реального эксперимента обучайте с --reviewed-only. Непроверенные записи в этом режиме исключаются до разбиения. Если независимых групп мало, разбиение завершится ошибкой — добавьте данные, а не убирайте группировку.
